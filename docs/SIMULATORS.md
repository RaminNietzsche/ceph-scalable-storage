# Interactive lab (web edition)

The web edition (`make site`) has eight small simulators, «آزمایشگاه تعاملی» / "Interactive lab". They run the algorithms the book explains, in the reader's browser, with no network and no installation: vanilla JavaScript, no libraries, no build step. Each one is embedded in the chapter that explains it (`::: {.sim name="…"}`; an optional `mode="…"` opens it in one of its modes, as chapters 2 and 37 open the placement lab in RBD mode) and has its own full page (`lab-<name>.html`); `lab.html` lists them and is linked from the sidebar and the home page.

The rule for every simulator: **the arithmetic is a port of Ceph's own code, and the tests compare it with that code.** Where a simulator only illustrates a sequence (peering, the write paths), the order of steps and every decision follow the named functions, and each step shows the file and function it comes from. The "How it works" panel of each simulator lists its sources and its limits.

## Files

| File | What it is |
|---|---|
| `templates/site/sims/sim-core.js` | The ported logic (no DOM): CRUSH hashes, `crush_ln`, the five bucket algorithms (uniform, list, tree, straw, straw2), `crush_do_rule`, PG seeds, the pg_autoscaler, EC/replication formulas, RGW shard and layout, BlueStore write decisions, the Striper. Loads in node and in the browser. |
| `templates/site/sims/crush-ln-table.js` | The `crush_ln` lookup tables from Ceph's `src/crush/crush_ln_table.h`, generated by `tools/simref/gen_golden.py --table`. LGPL-2.1 data, see `NOTICE.md`. |
| `templates/site/sims/sims.js`, `sim-*.js` | The user interface: helpers, one file per group of simulators, `sim-ui.js` mounts them. The same view code runs in node at build time for the static figure. |
| `templates/site/sims/strings-fa.yaml`, `strings-en.yaml` | All strings; the Persian file is the original, the English one its translation. |
| `templates/site/sims/sims.css` | Styles; light and dark themes use the site's variables. |
| `tools/sim_fallback.js` | Renders the static figure of each simulator (fixed state, every step shown) for `tools/build_site.py`. |
| `tools/simref/crush_ref.c`, `tools/simref/striper_ref.cc`, `tools/simref/gen_golden.py` | The reference: compiles Ceph's own C files and the Striper functions copied out of `src/osdc/Striper.cc`, and runs the real `module.py`, to produce `tests/sims/golden.json`. |
| `tests/sims/test_core.js` | The tests (`make check-sims`, part of `make check`). |

## How the numbers are checked

`make check-sims` runs `tests/sims/test_core.js` (node, no dependencies). It compares `sim-core.js` with `tests/sims/golden.json`, which `tools/simref/gen_golden.py` produces from a Ceph checkout:

- `crush_ref.c` includes Ceph's `src/crush/mapper.c`, links `hash.c`, `crush.c`, `builder.c` and `src/common/ceph_hash.cc`, builds maps with `crush_make_bucket` (straw2) and the rule steps of `CrushWrapper::add_simple_rule_at`, and runs `crush_do_rule`. The golden file holds the hashes, every one of the 65536 `crush_ln` values (as a checksum), 300 straw2 draws, `ceph_str_hash_rjenkins` and `ceph_str_hash_linux` of 55 names, and 108 maps (6 hierarchies × 3 weight/out variants × 6 rule and size combinations, replicated firstn and EC indep) with 8932 PG mappings. For the other bucket algorithms (`BA`, `SCV`, `BC`, `BW`, `BS` and `H4` commands of the harness) it adds 150 `crush_hash32_4` values, 40 single buckets of every algorithm with their builder weights and straw lengths and `crush_bucket_choose` for r = 0 … size+2 in one workspace at 40 inputs each (1600 sequences), and 432 maps built entirely of uniform, list, tree, straw or straw2 buckets, or mixing them (6 hierarchies × 3 variants × 4 rules), with 17632 PG mappings; `straw_calc_version` is 1, as the jewel tunables set it. The tests also check the chapter 28 worked examples (figures 28-5, 28-6, 28-7).
- The autoscaler cases import the real `src/pybind/mgr/pg_autoscaler/module.py` with small stubs for the mgr runtime and call its `_calculate_final_pool_pg_target`.
- The Striper: `gen_golden.py` cuts the bodies of `Striper::file_to_extents` (the lightweight overload), `object_truncate_size`, `get_num_objects` and `get_file_offset` and the `OrderByObject` comparator out of `src/osdc/Striper.cc` without changes and compiles them with g++ (`striper_ref.cc`, set `CXX` if g++ has another name) against the real `src/osdc/StriperTypes.h`; only logging, `ceph_assert` and boost's `small_vector` (as `std::vector`) are stood in for. The golden file holds 160 `file_to_extents` cases (orders 12 to 25, stripe units down to 1/64 of the object, stripe counts 1 to 16, truncation and buffer offsets; 141 span several objects), 80 cases of the other three functions, and data object names built as `CreateRequest::create_image` and `ImageCtx::init_layout` build them, with and without a data pool. The tests also use the vectors of Ceph's `src/test/test_striper.cc`, round-trip invariants (`file_to_extents` and `get_file_offset` agree, every byte lands exactly once), the book's chapter 37 example, the metadata object names and `generate_image_id`.
- The RGW shard index is checked against `ceph_str_hash_linux` from the C build and the chapter 4 examples (`photos/2026/11/img_0001.jpg` → shard 5 of 11).

To regenerate after a Ceph update:

```sh
CEPH_SRC=/path/to/ceph/src python3 tools/simref/gen_golden.py           # tests/sims/golden.json
CEPH_SRC=/path/to/ceph/src python3 tools/simref/gen_golden.py --table   # also crush-ln-table.js
node tests/sims/test_core.js
```

The golden file records the Ceph commit it was made from.

## Accessibility, print and motion

- Every control is a native `button`, `select` or `input` with a label; segmented choices are `role="radio"` groups with arrow keys; toggles carry `aria-pressed`, the information panel `aria-expanded`. Re-rendering keeps keyboard focus on the control that was used. Step changes are announced in a polite live region.
- Right-to-left: the Persian edition mirrors the sequence diagrams (time still runs with the reading direction) and isolates Latin tokens (`40'4`, function names, `[0,1,2]`) so the bidi order stays correct; numbers use Persian digits.
- Dark mode uses the site's theme variables.
- `prefers-reduced-motion`: no transitions; autoplay steps more slowly.
- Print and no JavaScript: each slot contains a static figure rendered at build time from the same view code (fixed state, every step listed, sources included). Print CSS hides the live simulator and shows that figure. The PDF, EPUB and DOCX editions print one line that points to the web edition's lab.

## Gamification

Using a simulator dispatches `sim:use`. `game.js` gives 5 XP for the first use of each simulator per day (cap 40 XP per day) and counts distinct simulators for the tiered «آزمایشگر» / "Experimenter" badge (1, 4 and 7 simulators). See `docs/GAMIFICATION.md`.

## Adding a simulator

1. Put the logic in `sim-core.js` with the Ceph file and function in a comment, and a test in `tests/sims/test_core.js` (golden data if the reference can be built).
2. Add `S.DEFS.<name> = { icon, defaults, refs, controls, view, input, act?, steps?, say?, fallbackState? }` in a `sim-*.js` file and list the file in `SIM_PARTS` (`tools/build_site.py`) and `tools/sim_fallback.js`.
3. Add the strings to both `strings-*.yaml` files and the name to `SIM_NAMES`.
4. Place `::: {.sim name="<name>"}` + `:::` in the Persian chapter and at the same place in the English one.
