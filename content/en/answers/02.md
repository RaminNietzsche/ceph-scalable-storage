1. Almost no data objects; only metadata objects (the header, the id and the directory entry, and the object map if it is enabled). RBD is thin, and a data object is created only after the first write to its corresponding range.
2. krbd is the kernel driver and creates a `/dev/rbdX` device; it is fast and suits physical hosts and Kubernetes, but its features depend on the kernel version. librbd is the complete user-space library that QEMU and OpenStack use. rbd-nbd builds a kernel block device on top of librbd; use it when you need a feature krbd lacks.
3. object-map keeps the existence state of objects in the client's memory and is valid only when a single client is the only writer; exclusive-lock guarantees exactly that exclusivity.
4. crash-consistent is like a power cut: whatever was on disk is recorded, but buffers and half-finished transactions are not. application-consistent is achieved by freezing the file system (fsfreeze or the guest agent) or by the application's own mechanism (a database's backup mode) before the snapshot.
5. In version 2 `snap protect` is not needed, and a parent snapshot that has children can be "deleted"; the snapshot is moved to the trash until the last child is flattened or deleted. It requires at least Mimic-compatible clients.
6. journal: RPO of a few seconds, roughly double the writes, librbd only. snapshot: RPO equal to the schedule interval, low overhead, also works with krbd.
7. rx-only means the local cluster only receives (one-way). rx-tx means both clusters can be source and target (two-way), and no reconfiguration is needed after a failover.
8. If the primary site is still alive and its clients are writing, two primaries with different histories come into existence (split-brain), and one of the two sets of changes has to be thrown away.
9. Demote the image in the primary site, resync it from the current primary, wait for the up+replaying state, then demote in the backup site and promote in the primary site.
10. The NVMe-oF gateway over TCP, with at least two gateways in a gateway group for HA; iSCSI is in maintenance mode.
