1. object_prefix and order (and, with custom striping, stripe_unit and stripe_count); each object's name is object_prefix followed by the object number as 16-digit hex.
2. The prefix becomes rbd_data.<metadata pool id>.<id>, so that objects of images from several pools that share one data pool do not collide.
3. name_<name>, which points to the id, and id_<id>, which points to the name.
4. Block 16, stripe 4, stripepos 0; so object 0 at offset 313568.
5. Two bits; object 0 is in the top two bits of the first byte (shift = 6).
6. So that updating one object rewrites only that 4 KiB block and its crc, without needing the whole map.
7. When a snapshot is taken, all EXISTS entries of the head become EXISTS_CLEAN; the next first write to that object turns it back to EXISTS.
8. DATA_UPDATED, because the EXISTS state (not EXISTS_CLEAN) means the object was written after the snapshot.
9. Because only one writer should change the map, so that the in-memory and RADOS states stay consistent; the lock owner is that writer.
10. It is the same as a namespace in RADOS, and all the listing objects (rbd_directory and the others) are created separately in each namespace; a client can be restricted to one namespace with a cap without creating a separate pool.
