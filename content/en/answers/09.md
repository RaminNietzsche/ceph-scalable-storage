1. مخزن آن آرشیو شده، آخرین نسخه‌اش ۲۰۱۶ است، فقط با نسخه‌های قدیمی Ceph کار می‌کرد و هیچ نگهداری یا به‌روزرسانی امنیتی ندارد.
2. گروه‌های ذخیره‌سازی به کلاس دستگاه و قانون‌های CRUSH، manifest سخت‌افزار به specهای cephadm و رابط وب به Ceph Dashboard تبدیل شدند.
3. چون یک ماژول MGR است و فقط ماژول‌های MGR فعال اجرا می‌شوند؛ با جابه‌جایی MGR آدرس تغییر می‌کند، مگر این‌که از redirect، load balancer یا mgmt-gateway استفاده شود.
4. Dashboard عملیات استقرار (میزبان، OSD، سرویس) را از طریق orchestrator (cephadm یا Rook) انجام می‌دهد؛ بدون آن این بخش‌ها فقط‌خواندنی‌اند.
5. تا رمز در تاریخچه‌ی shell و فهرست فرایندها دیده نشود.
6. scope حوزه‌ای از منابع (مثل pool یا rbd-image) است و نقش مجموعه‌ای از مجوزها (read، create، update، delete) روی چند scope.
7. چون SSO فقط هویت را تأیید می‌کند؛ کاربر باید در Dashboard تعریف شده باشد تا نقش و مجوزش مشخص شود.
8. نقطه‌ی ورود واحد با TLS برای Dashboard و ابزارهای پایش فراهم می‌کند و وابستگی آدرس به MGR فعال را حذف می‌کند؛ با oauth2-proxy احراز هویت متمرکز هم ممکن می‌شود.
9. REST API نسخه‌دار Dashboard برای عملیات، و Prometheus برای متریک‌ها.
10. چون Dashboard به MGR و MONها وابسته است و در بحران‌های جدی اولین چیزی است که از دسترس خارج می‌شود؛ پایش و هشدار باید مسیر مستقل داشته باشند.
