1. Collecting every counter of every daemon from one mgr reduced mgr performance in large clusters; ceph-exporter on each host reads only the local daemons from the admin socket.
2. Only the active mgr publishes cluster metrics; after a failover, a fixed target pointing at the previous mgr creates a blind spot.
3. ceph-exporter only publishes counters whose priority is at least exporter_prio_limit (default 5).
4. The ratio of the increase in sum to the increase in avgcount over that interval; in PromQL, the ratio of the rates of the two series _sum and _count.
5. One series per active health code with a name label; it allows precise alerting on codes such as SLOW_OPS or MON_DOWN.
6. The condition must hold for the whole for duration before the alert fires; it prevents alerts for transient events.
7. When a root alert (for example a host down) is active, it silences the secondary alerts it causes (the down OSDs of that host).
8. A single entry point with TLS and a virtual address for all interfaces, centralized authentication with oauth2-proxy, and secured monitoring endpoints.
9. Prometheus's security model assumes data is visible to anyone with access; its API reveals all collected (meta)data.
10. The percentage of time all of the pool's PGs are active, the 99th percentile of write latency, and for mirrored images the RPO (timestamp difference).
