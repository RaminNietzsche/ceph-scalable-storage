1. The zonegroup is the boundary of data replication: bucket data is replicated only between the zones of one zonegroup. The realm is the boundary of the namespace and metadata: users and buckets are unique and in sync across the whole realm.
2. A period is a named, epoch-numbered version of the realm configuration. Committing it publishes the new configuration to every zone so that they all agree on the structure and the master.
3. Sync inside radosgw instead of the external radosgw-agent; active-active instead of a read-only slave; and the realm and period concepts for versioned configuration and failover.
4. Creating a bucket is a metadata operation that must be recorded in the master zone, and the request is forwarded to the master; writing an object in an existing bucket is local and is synced later.
5. Zones use its key to read each other's logs and objects; it has full access to the realm's data and metadata, so exposing it means exposing all the data.
6. The time of the oldest change that has not yet been applied in this zone; its difference from the current time is an estimate of the real RPO.
7. Failover: in the healthy zone `zone modify --master --default`, `period update --commit` and an RGW restart, then a DNS change. Return: in the old zone `realm pull` and `period pull`, check that it has caught up, and if desired make it master again with a period commit.
8. enabled means sync happens; allowed means it is permitted but a lower level must enable it; forbidden means it is prohibited and a lower level cannot enable it either.
9. Protection against accidental and malicious deletion or overwriting, by keeping every version in a separate zone, without requiring versioning in the user zones.
10. A reshard changed the number and layout of index shards, and sync, which is based on each shard's bilog, was disrupted; since Reef, with the zone feature named resharding, each zone reshards independently without interrupting replication.
