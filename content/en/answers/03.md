1. One backend for all services (block, images, backup, file and object), end-to-end copy-on-write that makes VM creation instant, and shared storage that makes live migration and evacuate possible without moving disks; plus horizontal scaling and being open source.
2. Cinder and Nova only need to create clones from image snapshots; writing or deleting images is Glance's job. The principle of least privilege protects the images against mistakes or a compromise in cinder.
3. The image must be stored in Glance in raw format, and `show_image_direct_url = True` must be set so that Cinder sees the RBD address; and naturally both services must be connected to the same Ceph cluster.
4. QEMU gets the Ceph key from libvirt, and the domain XML only refers to the secret's UUID. During live migration the same XML goes to the destination host, so a secret with the same UUID must exist there too.
5. The VM's root disk becomes an image in the `vms` pool instead of a file on the local disk. If the compute node fails, the VM can be evacuated to another compute node because its disk is safe on Ceph.
6. The speed of volume creation (no flatten, deep clones) against chain dependencies and read performance. Flatten cuts the chain but takes more time and space.
7. Because it gives no protection against a failure or mistake in that same cluster (accidental deletion, a bug, an attacker with the admin key). Backups must be in another cluster or site.
8. The native driver uses the CephFS client directly in the guest (fast, but the guest needs network access to Ceph); the NFS driver exports shares through NFS-Ganesha (better isolation, one extra layer).
9. Because librbd honours the guest's flushes, and with `rbd cache writethrough until flush` the cache stays in writethrough mode until the guest has sent a flush.
10. So that the life cycles and upgrades of the two systems are independent, a problem in one does not spread to the other, and Ceph can serve other consumers (Kubernetes, S3) at the same time.
