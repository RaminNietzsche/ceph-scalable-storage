1. "ceph v2\n", a u16 length (16) and two u64s for the supported and required features; the current features are REVISION_1 and COMPRESSION.
2. So that it is a multiple of the AES block (16) and can be encrypted in secure mode without extra padding.
3. The preamble with seed zero over the first 28 bytes; the segments with seed 0xFFFFFFFF (−1).
4. So that the receiver can allocate a page-aligned buffer and hand the data to O_DIRECT without a copy.
5. The message header and small control frames are read with one decryption and one tag, and the length of the rest of the frame is known at once.
6. A downgrade attack, or tampering with the unencrypted bytes exchanged before auth, such as changing preferred_modes.
7. RESET when the session cookie is unknown to the server (for example after a restart); RETRY_GLOBAL when the client's global_seq is older than what the server has seen.
8. The message count, the policy bytes and the dispatch queue; when any of them fills up, reading from the socket stops and the TCP window slows the sender down.
9. Because epoll is in edge-triggered mode, and unread data does not create a new event.
10. It queues the event in external_events and wakes that worker's epoll_wait by writing to the eventfd (or pipe).
